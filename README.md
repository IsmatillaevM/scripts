# WinPE Backup

Автономный скрипт для резервного копирования пользовательского профиля Windows из WinPE (или из обычной Windows). Один `.cmd` файл, никаких зависимостей, работает в среде восстановления даже когда Windows не грузится.

Все сообщения на **узбекском (латиница)** — в WinPE часто нет шрифта с кириллицей.

Файл называется `b.cmd` — короткое имя, чтобы быстро набирать в консоли.

## Как запустить

### Шаг 1. Подготовка флешки

Положи файл `b.cmd` в **корень** USB-флешки (не в папку).

### Шаг 2. Зайти в среду восстановления (WinPE)

#### Способ A — через меню «Пуск» (если Windows грузится)

1. Нажми и держи **Shift**, затем кликни **Пуск → Питание → Перезагрузка**
2. Компьютер перезагрузится в меню **Выбор действия**
3. Иди: **Поиск и устранение неисправностей → Дополнительные параметры → Командная строка**
4. Выбери свою учётную запись и введи пароль
5. Откроется чёрное окно командной строки — ты в WinPE

#### Способ B — через загрузочную WinPE-флешку (если Windows не грузится)

1. Запиши WinPE-образ на другую флешку (через **Rufus**, **Ventoy** или **Win10XPE**)
2. Загрузись с этой флешки (в BIOS выбери её как Boot Device)
3. Когда откроется WinPE, нажми **Shift + F10** — появится командная строка

### Шаг 3. Узнать букву флешки через `diskpart`

В WinPE буква твоей флешки может отличаться от того, что было в обычной Windows (может быть `D:`, `E:`, `F:` — зависит от компьютера). Чтобы её узнать, выполни:

```cmd
diskpart
```

Откроется приглашение `DISKPART>`. Введи:

```cmd
list volume
```

Увидишь таблицу вроде:

```
  Том ###  Имя  Метка         ФС      Тип        Размер    Состояние  Св
  -------  ---  ------------  ------  ---------  --------  ---------  ---
  Том 0    C    Windows 11    NTFS    Раздел     475 Гб    Исправен
  Том 1         FAT32         Раздел  200 Мб     Исправен  Скр
  Том 2    E                  NTFS    Раздел     765 Мб    Исправен  Скр
  Том 3    D    MY_USB        FAT32   Сменный    14 Гб     Исправен
```

Найди строку с типом **Сменный** (`Removable`) и размером твоей флешки — это она. В примере выше буква — `D`.

Выйди из diskpart:

```cmd
exit
```

### Шаг 4. Запустить скрипт

Введи букву флешки + `\b`. Для примера выше:

```cmd
D:\b
```

Всё. Расширение `.cmd` можно не писать — Windows сама его подставит. Скрипт запустится, покажет найденные диски, профиль пользователя, оценит размер и начнёт копирование. На экране будет виден прогресс — названия копируемых файлов.

## Что копируется

### Пользовательские папки

**Основные папки профиля** — Desktop, Documents, Pictures, Videos, Music, Favorites, Links

**Downloads** — копируется всё, **кроме** установщиков: `.exe`, `.msi`, `.msix`, `.appx`, `.iso`, `.img`, `.vhd`, `.vhdx`, `.dmg`, `.pkg`, `.deb`, `.rpm`. Это сделано, чтобы не раздувать бэкап — установщики легко скачать заново.

**AppData\Roaming и AppData\Local** — копируется, но исключается мусор:
- Все браузерные кэши (`Cache`, `GPUCache`, `ShaderCache`, `Service Worker`, `IndexedDB` и т.д.)
- Логи и крэш-дампы (`Crashpad`, `CrashDumps`, `logs`, `Logs`)
- Временные файлы (`Temp`, `tmp`)
- Пакетные менеджеры (`node_modules`, `__pycache__`, `.venv`, `pip-cache`, `pnpm-cache`, `yarn-cache`)
- Системные пакеты (`Packages`, `PackageStaging`, `SquirrelTemp`)
- Браузерные истории и cookies
- Драйверные кэши (`NVIDIA`, `AMD`, `Intel`)

### Специальные данные

Каждая категория — в своей папке в корне бэкапа:

#### `_Bookmarks\` — Закладки браузеров
- **Chrome**: файл `Bookmarks` из `AppData\Local\Google\Chrome\User Data\Default\`
- **Edge**: аналогично из `AppData\Local\Microsoft\Edge\User Data\Default\`
- **Firefox**: вся папка `Profiles` из `AppData\Roaming\Mozilla\Firefox\`

Это чистые закладки без расширений и истории — минимум данных, максимум смысла.

#### `_Outlook\` — Почта Outlook (`.pst` / `.ost` / `.nst`)
Люди часто теряют почту при переустановке Windows, потому что `.pst` файлы лежат в неочевидных местах. Скрипт собирает их из трёх возможных мест:
- `Documents\Outlook Files\` (стандартное место для архивов)
- `AppData\Local\Microsoft\Outlook\` (кэш и `.ost`)
- `AppData\Roaming\Microsoft\Outlook\` (настройки + локальные `.pst`)

После восстановления Outlook: **File → Open & Export → Open Outlook Data File** → выбрать `.pst`.

#### `_RDP\` — Удалённые подключения
- Все `.rdp` файлы из `Documents\`
- `Default.rdp` (стандартный шаблон подключения)
- Папка `AppData\Local\Microsoft\Remote Desktop` — настройки нового приложения Remote Desktop

Так ты не потеряешь список своих серверов.

#### `_SSH\` — SSH-ключи и PuTTY-сессии
- Вся папка `.ssh\` из профиля (приватные ключи, `known_hosts`, `config`)
- `putty_sessions.reg` — экспорт сохранённых сессий PuTTY из ветки реестра `HKU\...\Software\SimonTatham`. В WinPE это делается через `reg load` офлайн-ульев `NTUSER.DAT` пользователя.

Для восстановления PuTTY — просто двойной клик по `putty_sessions.reg`.

**ВНИМАНИЕ:** приватные SSH-ключи — чувствительные данные. Храни бэкап в безопасном месте.

#### `_UserFonts\` — Пользовательские шрифты
Шрифты, установленные без прав админа (только для текущего пользователя) — из `AppData\Local\Microsoft\Windows\Fonts\`. Это те шрифты, которые устанавливаются двойным кликом без UAC.

#### `_StickyNotes\` — Стикеры рабочего стола
- `Modern\` — современные Sticky Notes (Microsoft Store app) из `AppData\Local\Packages\Microsoft.MicrosoftStickyNotes_*\LocalState\`
- `Legacy\` — старые Sticky Notes (Windows 7/8) из `AppData\Roaming\Microsoft\Sticky Notes\`

### Системная информация (`_SystemInfo\`)

Отдельная папка для метаданных о системе — всё, что поможет восстановить компьютер после переустановки Windows.

#### `installed_programs.txt` — Список установленных программ

Читается **напрямую из реестра** (`HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall` + ветка `WOW6432Node` для 32-bit программ).

**Почему не `wmic product`?** Казалось бы, он проще — но у него две проблемы:
1. Он **чудовищно медленный** — 10–20 минут на средней системе
2. Он триггерит **MSI self-repair** — Windows думает, что программы нужно проверить, и начинает их переустанавливать прямо во время запроса. Это может сломать установленный софт.

Поэтому только `reg query`. В WinPE система не загружена, поэтому скрипт подгружает `SOFTWARE` hive с системного диска офлайн через `reg load HKLM\OFFLINE_SW ...`, парсит ключи `DisplayName` и `DisplayVersion`, а потом выгружает hive. Результат — два списка (64-bit и 32-bit) в формате `Название | Версия`.

#### `WiFi\` — Wi-Fi профили с паролями

Поведение зависит от режима:

**В живой Windows:**
- `netsh wlan export profile key=clear folder=...` создаёт XML-файл для каждой точки доступа — с паролем в открытом виде
- Плюс отдельный читаемый файл `_wifi_passwords.txt`:
  ```
  Wi-Fi profiles (SSID : parol)
  ================================
  Home_Network : mypassword123
  Office_WiFi  : OfficePass2024
  Starbucks    : [ochiq tarmoq]
  ```

**В WinPE (система не загружена):**
- Скрипт копирует **сырые XML-профили** из `C:\ProgramData\Microsoft\Wlansvc\Profiles\Interfaces\`
- Пароли в этих XML зашифрованы через **DPAPI** (Data Protection API) ключом пользователя Windows
- Расшифровать их можно **только на оригинальной Windows** с тем же пользователем — это защита Microsoft, обойти её нельзя
- Поэтому в папку кладётся `_README.txt` с инструкцией: загрузи обратно родной Windows и выполни `netsh wlan show profile name="SSID" key=clear`

Для восстановления Wi-Fi на новой системе:
```cmd
netsh wlan add profile filename="E:\...\WiFi\Home_Network.xml"
```

#### `windows_product_key.txt` — Ключ Windows

Содержит:
- **OEM-ключ из BIOS** — через `wmic path softwarelicensingservice get OA3xOriginalProductKey`. Это тот ключ, который производитель зашил в UEFI/BIOS при изготовлении ноутбука. Он **не теряется** при переустановке Windows и позволяет активировать систему без ввода.
- **Описание ключа** — какая редакция (Home / Pro / Education)
- `ProductName`, `EditionID`, `ProductId` из реестра — какая версия сейчас стоит

Пригодится, если устанавливаешь Windows с нуля и она не активируется автоматически.

#### `Drivers\` — Экспорт всех драйверов

Через `DISM /image:C:\ /export-driver /destination:...` — вытаскивает все сторонние драйверы, установленные в системе (Wi-Fi адаптер, принтер, видеокарта, тачпад и т.д.).

После переустановки Windows на том же железе:
```cmd
pnputil /add-driver E:\...\Drivers\*.inf /subdirs /install
```
И все драйверы вернутся одной командой. Экономит часы ковыряния на сайте производителя.

#### `hardware.txt` — Паспорт железа

Через `wmic`:
- **CPU** — модель, количество ядер, частота
- **RAM** — ёмкость каждой планки, частота, производитель
- **GPU** — видеокарты и объём памяти
- **Диски** — модели SSD/HDD, размер, тип носителя
- **Motherboard** — производитель, модель, версия
- **BIOS** — вендор, версия, дата прошивки

Полезно, если нужно купить такую же планку памяти, обновить BIOS или понять, какие драйверы искать.

#### `hosts` — Файл hosts

Копия `C:\Windows\System32\drivers\etc\hosts`. Если ты правил его вручную (блокировал рекламу, прописывал локальные домены для разработки) — не потеряется.

Для восстановления: скопируй обратно в тот же путь (нужны права админа).

#### `ScheduledTasks\` — Планировщик задач

- `tasks_list.csv` — общая таблица со всеми задачами, их статусом, расписанием
- Отдельный `.xml` файл для **каждой задачи** через `schtasks /query /tn "..." /xml`

XML содержит полное определение задачи — для восстановления:
```cmd
schtasks /create /tn "Моя задача" /xml "E:\...\ScheduledTasks\Моя_задача.xml"
```

Удобно, если ты настроил свои бэкапы, автозапуск программ, напоминания — не придётся настраивать заново.

#### `Certs\` — Пользовательские сертификаты

Через `certutil -store -user` — три файла:
- `user_personal.txt` — хранилище `My` (личные сертификаты)
- `user_trusted_root.txt` — доверенные корневые
- `user_intermediate.txt` — промежуточные CA

**Важно:** это только **список** сертификатов (отпечатки, серийники, темы). Приватные ключи `certutil` без пароля не экспортирует. Если нужен сертификат с ключом — используй:
```cmd
certutil -user -exportPFX my <SerialNumber> cert.pfx
```
Инструкция про это лежит рядом в `_README.txt`.

### Проверка свободного места

Перед копированием скрипт покажет:
- Размер профиля пользователя (например `42 GB`)
- Свободное место на флешке (например `14 GB`)

Если **данные не влезают** — выведет большое предупреждение:
```
============================================================
[!] DIQQAT: ma'lumotlar fleshkaga sig'maydi!
    Profil hajmi:        42 GB
    Fleshkada bo'sh joy: 14 GB
    Kerak bo'ladi:       taxminan 42 GB
============================================================
```

И спросит, продолжать или нет. Если продолжить — скопируется то, что влезет, остальное даст ошибку «нет места».

## Что НЕ копируется (специально)

- **Файлы установщиков** в Downloads (чтобы не раздувать бэкап)
- **Кэши браузеров** (миллионы мелких файлов, которые пересоздаются сами)
- **Node modules, pip cache, Docker images** (легко восстановить)
- **Папка Public** (не относится к конкретному пользователю)
- **Служебные профили** (`Default`, `Public`, `defaultuser0`, `WDAGUtilityAccount`)
- **Файлы системного мусора**: `Thumbs.db`, `desktop.ini`, `*.tmp`, `*.log1`, `*.etl`
- **Корзина** (`$Recycle.Bin`) и `System Volume Information`

Если нужно скопировать что-то из исключённого — отредактируй список `/XD` / `/XF` в соответствующей функции `b.cmd`.

## HTML-отчёт

После завершения в корне бэкапа появится `report.html` — красивая **автономная** страница в тёмной теме (стиль VS Code / Tailwind), работает **офлайн без интернета**.

### Что внутри

**Метаданные** вверху:
- Имя пользователя
- Папка-источник (откуда копировали)
- Папка-назначение (куда скопировали)
- Дата и время бэкапа
- Общий размер в GB

**Карточки по категориям файлов** — grid из плиток, в каждой:
- Название категории (`Documents`, `Images`, `Videos`, `Audio`, `Archives`, `Code`, `Executables`)
- Количество файлов — крупной цифрой
- **Пропорциональная полоска** — визуальное сравнение размеров категорий (у кого больше файлов — у того длиннее)

Расширения, которые идут в каждую категорию:
- **Documents**: pdf, doc, docx, odt, rtf, txt, md, xls, xlsx, ods, csv, ppt, pptx, odp
- **Images**: jpg, jpeg, png, gif, bmp, tiff, webp, svg, heic, raw, cr2, nef, arw
- **Videos**: mp4, mkv, avi, mov, wmv, flv, webm, m4v, mpg, mpeg, 3gp
- **Audio**: mp3, wav, flac, aac, ogg, m4a, wma, opus
- **Archives**: zip, rar, 7z, tar, gz, bz2, xz, iso
- **Code**: py, js, ts, java, c, cpp, h, hpp, cs, go, rs, rb, php, html, css, sql, sh, ps1, ipynb
- **Executables**: exe, msi, msix, appx, bat, cmd, ps1, app

**Таблица Top 20 самых больших файлов** — отсортирована по убыванию, с размерами в MB и полными путями. Сразу видно, что занимает место (обычно это видео или виртуальные машины).

**Список скопированных папок** — какие секции бэкапа заполнены.

### Как открыть

Двойной клик по `report.html` на флешке — откроется в любом браузере. Всё работает без интернета, без зависимостей, тёмная тема по умолчанию, адаптивная вёрстка (нормально смотрится и на телефоне).

## Требования

### Минимальные
- **Windows 7** и новее, или **любой WinPE**
- Доступ к командной строке
- Флешка/внешний диск с достаточным местом (скрипт покажет оценку)

### Для полной функциональности
- **Права администратора** (без них часть AppData пропустится — в WinPE это по умолчанию)
- **`robocopy`** (есть во всех Windows с Vista)
- **`DISM`** — для экспорта драйверов (есть в Win 7+)
- **`certutil`** — для сертификатов (есть в Win 7+)

### Опционально
- `wmic` — если нет (новый Windows 11 PE), скрипт переключится на PowerShell или `fsutil`
- PowerShell — fallback для определения дисков
